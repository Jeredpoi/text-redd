# Литера

Текстовый редактор для Windows на Electron с богатым форматированием (как в Word) и проверкой орфографии на русском и английском языках.

## Возможности

- Стартовый экран новой вкладки: приветствие, шаблоны документов (заметка, письмо, список дел, отчёт) и сетка недавних файлов — как в Google Docs; исчезает, как только начинаете печатать
- Ползунок масштаба в статус-баре (50–200%, клик по проценту — сброс) и режим фокуса (F9 или «Инструменты» → «Режим фокуса»): скрывается всё, кроме страницы, выход — Esc
- Вкладки для нескольких документов в одном окне — ведут себя как во всех браузерах: перетаскивание для смены порядка, закрытие средним кликом мыши, крестик виден только у активной/наведённой вкладки, Ctrl+Tab/Ctrl+Shift+Tab — переключение, Ctrl+1…8 — переход к вкладке по номеру, Ctrl+9 — последняя. У каждой вкладки свой файл и статус изменений
- Никакого системного меню — все команды (файл, вставка, настройки) на самой ленте; горячие клавиши работают как обычно
- Боковая панель: поиск и список недавних файлов, оглавление текущего документа (переход по заголовкам H1–H3), сворачивается в узкую полосу
- Лента с пятью вкладками — «Файл» (открыть/сохранить/экспорт/печать/настройки), «Правка» (отменить/повторить/вырезать/копировать/вставить/очистить формат), «Вставка», «Формат» (форматирование текста), «Инструменты» (статистика документа)
- Заголовок документа над текстом (шрифт Lora) — это и есть имя файла: как напишете, так документ и назовётся при сохранении, а переименование заголовка уже сохранённого файла переименует и сам файл на диске
- Всплывающая панель форматирования при выделении текста: шрифт, размер, жирный/курсив/подчёркнутый/зачёркнутый, палитры цвета текста и выделения, вставка ссылки, очистка форматирования
- Автосохранение: если задана папка по умолчанию (Настройки → Файлы), документы сохраняются на диск сами — почти сразу после паузы в наборе текста и не реже, чем раз в N секунд; если папка не задана, автосохранение пишет черновик во внутреннюю папку восстановления (см. ниже)
- Восстановление после сбоя: если приложение закрылось некорректно, при следующем запуске предложит восстановить несохранённые вкладки
- Окно «Настройки»: тема, шрифт и размер по умолчанию, автосохранение (вкл/выкл и интервал), языки проверки орфографии, формат и папка сохранения по умолчанию
- Форматирование текста: жирный, курсив, подчёркнутый, зачёркнутый, палитра цветов текста и выделения (как в Google Docs, с произвольным цветом через «Другой», рядом недавно использованные цвета и пипетка для выбора цвета прямо с экрана); повторный клик по уже применённому цвету выделения снимает его
- Выбранный шрифт/размер без выделения текста действует на то, что печатается дальше (как в Word)
- Шрифт и размер шрифта отражают то, что реально стоит под курсором; размер — свободное поле с вводом любого числа и подсказками стандартных размеров Word (8–72)
- Больше 20 шрифтов (Arial, Georgia, Montserrat, Playfair Display и др.)
- Стили абзацев: заголовки H1–H3, обычный текст, цитата, код; межстрочный интервал (одинарный/1,15/1,5/двойной); надстрочный и подстрочный знак (x², x₂)
- Списки (маркированные и нумерованные), отступы, выравнивание
- Вставка таблиц и ссылок через аккуратные диалоговые окна, вставка изображений, горизонтальных линий и чек-листов (кликабельные галочки, выполненные пункты зачёркиваются)
- Редактирование таблиц: правый клик по ячейке — вставить/удалить строку или столбец, удалить таблицу
- Проверка орфографии на лету (русский + английский) — красное подчёркивание ошибок и варианты исправления по правому клику
- Поиск и замена, со счётчиком совпадений
- Сохранение и открытие файлов в форматах Word (.docx, по умолчанию), .txt и .html; формат можно поменять в настройках
- В .docx корректно сохраняются цвета, шрифты, размеры, интервалы и чек-листы (галочки превращаются в ☑/☐ и восстанавливаются при открытии). Ограничение: при переоткрытии .docx в Литере цвета/шрифты/размеры упрощаются (Word показывает их полностью); для стопроцентной точности при повторном редактировании используйте формат .html
- Экспорт в PDF
- Печать документа
- Тёмная (по умолчанию) и светлая тема
- Автообновление: при запуске (и по кнопке «Обновления» на ленте «Файл») приложение само проверяет, не вышла ли новая версия, и предлагает скачать и установить её в аккуратном окне — без ручной пересборки
- Недавние файлы: правый клик — «Открыть» / «Показать в проводнике» / «Удалить из списка»
- Правый клик по полосе вкладок — «Новая вкладка» / «Закрыть вкладку» / «Закрыть остальные»
- Счётчик слов и символов и приблизительное время чтения — в статус-баре и на вкладке «Инструменты»
- Имя файла и метка несохранённых изменений в заголовке окна, в статус-баре и на самой вкладке
- Предупреждение о несохранённых изменениях при закрытии вкладки или окна

## Структура проекта

```
Litera/
├── main.js          — главный процесс Electron (окно, файлы, экспорт, настройки, автосохранение)
├── preload.js       — безопасный мост между main и renderer
├── index.html        — разметка редактора и панели инструментов
├── renderer.js       — логика редактора (форматирование, файлы, поиск)
├── styles.css        — оформление, светлая/тёмная тема
├── package.json       — зависимости и настройки сборки
└── build/
    ├── icon.ico       — иконка приложения
    └── build.bat      — скрипт для сборки установщика одной кнопкой
```

## Установщик (.exe)

Установщик — один файл `Литера Setup X.X.X.exe` (несколько мегабайт). Это «веб-установщик» (electron-builder `nsis-web`): пользователь скачивает только его, запускает — и установщик **сам** скачивает остальные файлы приложения с GitHub, распаковывает их и завершает установку. Никакого отдельного архива, никаких дополнительных файлов рядом, никакого `build.bat` пользователю отдавать не нужно — для установки нужен только этот один `.exe` и интернет-соединение на момент установки (файлы скачиваются с GitHub Releases того же репозитория).

### Как собрать и опубликовать установщик — через GitHub Actions (рекомендуется)

Самый простой способ — переложить сборку на GitHub, чтобы не делать это руками на своём Windows-компьютере:

1. Поднимите версию в `package.json` (поле `version`), закоммитьте.
2. Создайте и запушьте тег вида `v1.0.1` (тег должен совпадать с версией в `package.json`):
   ```
   git tag v1.0.1
   git push origin v1.0.1
   ```
3. GitHub Actions (`.github/workflows/release.yml`) сам соберёт установщик на настоящей машине с Windows и опубликует его как GitHub Release — со всеми нужными файлами (маленький `Setup.exe` + пакет с самим приложением, который он скачивает при установке).
4. Готово — пользователи получают ссылку на Release и качают один `.exe`; уже установленные копии приложения увидят обновление сами (см. «Автообновление» ниже).

Workflow также можно запустить вручную из вкладки **Actions** на GitHub (кнопка «Run workflow»), без создания тега — полезно для тестовой сборки.

### Как собрать установщик вручную (на своём компьютере с Windows)

Нужно, только если не хотите пользоваться GitHub Actions. `build.bat` — инструмент для разработчика; обычные пользователи его не видят и не запускают.

1. Установите [Node.js](https://nodejs.org) (LTS-версия, 18 или новее).
2. Скопируйте папку `Litera` на свой компьютер.
3. Запустите `build\build.bat` двойным щелчком — он поставит зависимости и соберёт установщик.
4. Готовый установщик появится в `dist_installer\` (небольшой файл `Литера Setup X.X.X.exe` + пакет `Литера-X.X.X-x64.nsis.7z` + `latest.yml`) — все три файла нужно прикрепить как ассеты к GitHub Release с тегом `vX.X.X`, иначе установщик и автообновление не найдут, что скачивать.

Либо вручную из командной строки:

```
npm install
npm run dist
```

### Предупреждение Windows «Защитник SmartScreen»

Если установщик не подписан цифровой подписью (сертификат code signing стоит денег и для личного проекта обычно не нужен), Windows при первом запуске `.exe` может показать синий экран «Windows защитила ваш компьютер». Это нормально для любых непромышленных приложений без подписи и не означает, что с файлом что-то не так — нужно нажать «Подробнее» → «Выполнить в любом случае».

### Возможная ошибка при сборке: "symbolic link" / "privilege"

`electron-builder` при сборке скачивает вспомогательный архив с инструментами
и пытается создать в нём символические ссылки. По умолчанию Windows
запрещает это обычным пользователям, из-за чего сборка падает с ошибкой про
отсутствие прав (актуально только при ручной сборке на своём компьютере —
GitHub Actions эту проблему не встречает). Есть два способа исправить:

1. Включить режим разработчика: **Параметры → Конфиденциальность и защита →
   Для разработчиков → Режим разработчика** (переключить в «Вкл»), затем
   запустить `build.bat` ещё раз. Это разовая настройка.
2. Либо запустить `build.bat` от имени администратора (правая кнопка мыши →
   «Запуск от имени администратора»).

## Настройка словаря

Проверка орфографии встроена в Electron/Chromium и включена для языков `ru` и `en-US` (см. `main.js`, вызов `setSpellCheckerLanguages`). Ничего дополнительно ставить не нужно — словари подтягиваются автоматически при первом запуске (нужен доступ в интернет один раз для скачивания hunspell-словарей).

## Шрифт страницы

Текст документа набран шрифтом Lora (Google Fonts) — подключается через интернет при запуске. Без подключения к интернету автоматически используется запасной шрифт (Georgia), интерфейс продолжает работать как обычно.

## Горячие клавиши

Системного меню нет, поэтому все привычные сочетания работают напрямую:

- `Ctrl+N` — новая вкладка, `Ctrl+W` — закрыть вкладку (или средний клик по вкладке)
- `Ctrl+Tab` / `Ctrl+Shift+Tab` — следующая/предыдущая вкладка, `Ctrl+1`…`8` — вкладка по номеру, `Ctrl+9` — последняя
- `Ctrl+O` — открыть, `Ctrl+S` — сохранить, `Ctrl+Shift+S` — сохранить как
- `Ctrl+P` — печать, `Ctrl+F` — найти и заменить, `Ctrl+K` — вставить ссылку, `Ctrl+\` — очистить форматирование
- `Ctrl+Z` / `Ctrl+Y` — отменить/повторить, `Ctrl+X/C/V` — вырезать/копировать/вставить, `Ctrl+Shift+V` — вставить без форматирования, `Ctrl+A` — выделить всё (работают нативно, без меню)
- `Ctrl+=` / `Ctrl+-` / `Ctrl+0` — масштаб, `F11` — на весь экран, `F12` / `Ctrl+Shift+I` — инструменты разработчика

## Автосохранение и восстановление

Автосохранение (Настройки → Автосохранение) срабатывает почти сразу после паузы в наборе текста (~2 секунды) и не реже, чем раз в N секунд (по умолчанию 20) — на случай, если печатать без остановки.

- **Если задана папка по умолчанию** (Настройки → Файлы → «Папка по умолчанию»): автосохранение пишет по-настоящему на диск. Новый документ без имени файла сам сохранится в эту папку под своим заголовком (без диалога «Сохранить как»), а уже открытые файлы просто пересохраняются.
- **Если папка не задана**: автосохранение пишет черновик во внутреннюю папку `recovery` профиля приложения — реальный файл на диске не трогается, это только страховка на случай сбоя. Черновик удаляется сразу после обычного сохранения (Ctrl+S) или явного отказа от изменений. Если приложение закрылось некорректно и черновики остались, при следующем запуске появится окно с предложением их восстановить.

## Автообновление

Приложение умеет само проверять, не вышла ли более новая версия, и предлагать обновиться — в красивом окне, а не через системные диалоги. Проверка идёт через **GitHub Releases** репозитория `jeredpoi/text-redd` (библиотека `electron-updater`).

Как это выглядит для пользователя:

1. При запуске (через несколько секунд после старта) и по кнопке **«Обновления»** на ленте «Файл» (или ссылке «Проверить обновления» в Настройках) приложение тихо проверяет GitHub Releases.
2. Если найдена версия новее текущей — появляется окно «Доступно обновление» с кнопками **«Позже»** и **«Скачать и установить»**.
3. Скачивание начинается только после явного нажатия «Скачать и установить» (автоматически ничего не скачивается без разрешения) — в окне показывается прогресс.
4. Когда файл загружен, кнопка меняется на **«Перезапустить и установить»** — по нажатию приложение закрывается и запускает установщик новой версии, установка происходит поверх старой.

### Как выпустить новую версию (для разработчика)

Проще всего — через тег и GitHub Actions (см. раздел «Установщик» выше): поднять версию → `git tag vX.X.X` → `git push origin vX.X.X` → сборка и публикация Release происходят сами. У пользователей, при следующем запуске приложения или нажатии «Обновления», появится предложение обновиться.

Промежуточные сборки для себя (без тега/публикации релиза) можно не трогать — без опубликованного релиза на GitHub автообновление просто ничего не найдёт и не побеспокоит пользователя.
